# АрендаТЦ — MVP электронной системы сдачи в аренду торговых площадей

Рабочий прототип на реальном стеке по проекту из лабораторной работы:
**Django 5.2 + Django REST Framework + PostgreSQL 16**, запуск одной командой через Docker Compose.

Реализован ключевой путь:

```
каталог и план этажа → заявка с бронью → одобрение менеджером → договор по шаблону
→ утверждение руководителем (ЭП) → подписание арендатором (ЭП)
→ ежемесячные счета → импорт банковской выписки → распределение оплат → пени → отчёты
```

## Запуск

Нужен только Docker Desktop (или Docker Engine с плагином compose).

```bash
docker compose up --build
```

Откройте http://localhost:8000. При первом запуске база заполняется демо-данными:
3 этажа, 30 помещений, 4 арендатора, 6 договоров, история счетов и оплат.

Пароль всех демо-пользователей — `demo12345`.

| Логин | Роль | Что посмотреть |
| --- | --- | --- |
| `tenant1` | Арендатор ООО «Ромашка» | Кабинет с просроченным долгом и пенями |
| `tenant2` | Арендатор ИП Соколова | Подача заявки, подписание договора |
| `manager` | Менеджер по аренде | Очередь заявок, формирование договора |
| `director` | Руководитель | Утверждение договора, дашборд |
| `accountant` | Бухгалтер | Начисления, загрузка выписки, привязка платежей |
| `admin` | Администратор | Админка Django: `/admin/` |

Остановить: `docker compose down`. Удалить и данные: `docker compose down -v`.

### Сценарий для демонстрации (5 минут)

1. Войдите как `tenant2` → «Каталог» → выберите зелёное помещение на плане → подайте заявку.
   Помещение станет жёлтым: оно забронировано на 5 рабочих дней.
2. Войдите как `manager` → «Заявки» → «Одобрить» → «Сформировать договор» → «Отправить на утверждение».
3. Войдите как `director` → откройте договор → «Утвердить и подписать ЭП».
4. Войдите как `tenant2` → «Мой кабинет» → «Подписать». Договор вступит в силу, выставится счёт на обеспечительный платёж.
5. Войдите как `accountant` → «Начисления» → «Загрузить выписку» → файл `sample_data/statement_example.csv`.
   Один платёж распределится по долгам «Ромашки», второй попадёт в «нераспознанные» для ручной привязки.
6. Попробуйте подать вторую заявку на то же помещение и тот же период — система откажет.

## Запуск без Docker

Нужны Python 3.12+ и PostgreSQL 14+.

```bash
python -m venv .venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt
createdb arendatc                                       # или через pgAdmin
export POSTGRES_USER=postgres POSTGRES_PASSWORD=...     # Windows: set POSTGRES_USER=...
python manage.py migrate
python manage.py seed_demo
python manage.py runserver
```

Пользователю БД нужно право создать расширение `btree_gist` (в Docker-образе PostgreSQL оно есть по умолчанию).

## Тесты

```bash
docker compose run --rm web python manage.py test          # в Docker
python manage.py test                                       # локально
```

28 тестов, все на реальной PostgreSQL. Среди них:

- ограничения `EXCLUDE` не дают создать пересекающиеся брони и договоры даже в обход бизнес-логики;
- две **одновременные** заявки на одно помещение из разных потоков — успешна ровно одна;
- полный цикл заявка → договор → подписи → счета, возврат на доработку, истечение брони;
- пропорциональное начисление за неполный месяц, FIFO-распределение оплат, авансы, пени без двойного начисления;
- права ролей в вебе и API, проверка ИНН/ОГРН при регистрации.

## Как устроено

```
config/      настройки, маршруты
accounts/    пользователи с ролями, арендаторы, проверка ИНН/ОГРН
catalog/     этажи, помещения, фильтры и проверка доступности
leasing/     заявки, брони, договоры, версии договоров; services.py — вся логика переходов
finance/     счета, платежи, распределение оплат; services.py — начисления, выписка, пени
core/        дашборд и отчёты, регламентные задачи, демо-данные, тесты
api/         REST API (DRF), документация OpenAPI
templates/   страницы (Bootstrap 5, без сборки фронтенда)
```

**Защита от двойной сдачи — два независимых рубежа.**
1. Сервис блокирует строку помещения (`SELECT … FOR UPDATE`), поэтому параллельные заявки обрабатываются по очереди.
2. В PostgreSQL заданы ограничения `EXCLUDE USING gist (premises_id WITH =, daterange(…) WITH &&)` для активных броней и действующих договоров. Даже ошибка в коде не позволит записать пересечение.

**Регламентные задачи** выполняет контейнер `scheduler` (`python manage.py run_scheduler`) раз в минуту:
снимает просроченные брони и отменяет незаключённые по ним договоры, завершает истёкшие договоры,
выставляет счета за текущий месяц, пересчитывает пени. Все задачи идемпотентны.
Разовый запуск: `python manage.py run_scheduler --once`.

### REST API

Интерактивная документация — http://localhost:8000/api/docs/ (Swagger UI загружается из интернета).
Авторизация — сессия браузера или Basic Auth.

| Метод и путь | Кто | Назначение |
| --- | --- | --- |
| `GET /api/premises/?floor=&type=&area_min=&period_from=&period_to=` | все | Поиск помещений |
| `POST /api/applications/` | арендатор | Заявка с бронью; `409` если занято |
| `POST /api/applications/{id}/approve/`, `/reject/` | менеджер | Решение по заявке |
| `POST /api/contracts/from-application/` | менеджер | Сформировать договор |
| `POST /api/contracts/{id}/send-for-approval/` | менеджер | На утверждение |
| `POST /api/contracts/{id}/approve/` | руководитель | Утвердить и подписать |
| `POST /api/contracts/{id}/sign/` | арендатор | Подписать |
| `GET /api/invoices/`, `POST /api/invoices/generate/` | арендатор / бухгалтер | Счета, начисление за месяц |
| `POST /api/payments/import/` | бухгалтер | Загрузить выписку CSV |
| `GET /api/reports/occupancy/`, `/api/reports/debt/` | сотрудники | Отчёты |

Пример:

```bash
curl -u tenant2:demo12345 -H "Content-Type: application/json" \
  -d '{"premises": 4, "lease_from": "2026-12-01", "lease_to": "2027-11-30", "activity": "магазин"}' \
  http://localhost:8000/api/applications/
```

## Отличия MVP от проекта

| В проекте | В MVP | Почему |
| --- | --- | --- |
| Подпись УКЭП через оператора ЭДО | Хеш SHA-256 от версии договора, подписанта и времени | Нужны договор с оператором и сертификаты; интерфейс функции сохранён |
| Проверка ИНН через API ФНС | Проверка контрольных сумм ИНН/ОГРН | Нужен ключ API |
| Обмен с 1С | Нет | Вне ключевого пути |
| React SPA | Серверные страницы Django + Bootstrap | Быстрее для MVP, без сборки |
| Celery + Redis | Один процесс `run_scheduler` | Задачи лёгкие и идемпотентны |
| Генерация PDF (docxtpl) | HTML-печатная форма, «Сохранить в PDF» из браузера | Без внешних зависимостей |
| Обращения арендаторов, отчёт о доходности | Нет | Вне ключевого пути |
| Поле брони `valid_from/valid_to` | `lease_from/lease_to` + `expires_at` | Бронь блокирует именно период аренды |

Праздничные дни при расчёте срока брони не учитываются — только выходные.
